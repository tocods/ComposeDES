# ComposeDES 论文机制符合度评估

评估日期：2026-09-10  
评估版本：`v2.0.0-alpha.4.2`  
论文基准：仓库根目录 `论文.tex`  
代码基准：integration `5280a48`、FNCS `2df6dda`、GPUSim `09861db`、ns-3 `2f049f0d4`

## 1. 结论

当前实现与论文总体机制的加权符合度为 **59/100**。

这个分数应分层理解：

| 维度 | 符合度 | 结论 |
|---|---:|---|
| 总体架构与控制权边界 | 77% | 基本符合，DAG 控制面已经从 GPUSim 移到中间件 |
| Active-dependency 时间协调 | 52% | 有动态依赖调度和保守回退，但没有实现论文定义的逐边 lower bound/frontier 协议 |
| Critical-path event acceleration | 56% | 有静态证书、选择性细化和真实 backend-local chain；通用资源包络宏事件仍未实现 |
| 论文实验论证完整度 | 45% | 有小型机制测试和 case study，但缺少投稿所需的大规模消融、wall-clock 加速和硬件准确度证据 |

因此，当前系统可以准确表述为：**已经形成可运行的中间件 DAG 控制面原型，并实现了论文两项优化机制的受限版本。** 目前不能无保留地声称论文中描述的三项机制均已完整实现并被实验验证。

## 2. 评分方法

评分只计算论文可核查的机制和证据，不因代码量、NeuSight 自身准确度或界面完整度加分。

| 类别 | 权重 | 得分 |
|---|---:|---:|
| A. Application-to-DES composition | 30 | 23 |
| B. Active-dependency coordination | 25 | 13 |
| C. Critical-path event acceleration | 25 | 14 |
| D. Validation、性能和可复现证据 | 20 | 9 |
| **总计** | **100** | **59** |

“部分实现”按实际覆盖范围折算。仅存在接口、静态输入字段或小型单元测试，不等价于论文所述完整运行时机制。

## 3. 已经符合的核心内容

### 3.1 DAG 控制面归属正确

论文要求 coordinator 持有 executable graph，负责依赖释放、事件下发和终止判断。当前 `WorkflowController` 已持有任务状态、父子依赖、边状态、collective 状态和在途集合；GPUSim worker 接收 `compute.dispatch`，ns-3 worker 接收 `network.dispatch`。后继任务只由中间件在收到 backend completion 后释放。

这部分已经满足协同仿真的核心边界：

- broker 只负责发布订阅和逻辑时间协调，不解析 AI/HPC DAG；
- GPUSim 只负责计算资源内部执行、排队和完成时间；
- ns-3 只负责网络流的路由、链路占用、排队和完成；
- orchestrator 是 DAG 完成和 `control.end` 的唯一判定者；
- 相同逻辑时间、相同 topic 的多事件编码为一个 JSON batch，每个事件身份仍独立保留。

### 3.2 计算和通信都经过真实领域仿真器

NeuSight 只产生计算代价和任务描述，不作为运行时模拟器。GPUSim 将下发任务转换为真实 `GpuJob`；跨主机边和 collective flow 由 ns-3 执行。alpha.4 大型实验使用 ns-3 store-and-forward flow 模型，小型校准保留 packet 模式。

需要保持当前报告中的精度边界：flow macro 与 packet 模式是两个不同精度层级，不能把二者数值不一致解释为控制面误差。

### 3.3 Collective 由中间件展开

中间件支持 Ring `AllReduce`、`AllGather`、`ReduceScatter` 和 `AllToAll`。它逐 step 下发 flow，并在一个 step 的全部 flow 完成后才进入下一 step。2-rank Ring AllReduce 小型测试验证了 barrier 后继不会提前释放。

### 3.4 Backend-local chain 已成为真实的同 owner 执行

alpha.4.2 新增默认关闭的 `--backend-local-chains`。开启后，中间件只选择同主机、零字节、单入单出、不跨 collective、无重试且同主机资源顺序确定的链，下发一个 `compute.plan.dispatch`。

GPUSim 仍逐个执行原始 `GpuJob`，不把计算时间简单相加，也不替换为预测值。已有两组 A/B 结果：

| 场景 | 原始/优化 makespan | 轨迹等价性 | dispatch | scheduler rounds |
|---|---:|---|---:|---:|
| H100，29 compute，0 network | 569683 us | 每任务 start/finish 完全一致 | 29 -> 1 | 651 -> 602 |
| PP4，29 compute，3 network | 640153.312 us | 每任务和网络 completion 完全一致 | 29 -> 4 | 729 -> 683 |

这满足论文“本地同 owner 边可以留在 backend，且不能改变边界 trace”的受限线性链情形。

### 3.5 基本安全机制存在

- event、attempt、transfer 和 batch 均有稳定标识；
- orchestrator 和 worker 对重复事件做幂等处理；
- broker 检查消息时间不能早于接收方已推进的时间；
- active-dependency 模式失败或形成环时可回退到全局保守规则；
- orchestrator 按 logical time、microstep、topic 和 event id 排序输入；
- DAG 终止时检查全部任务终态且 compute/network inflight 均为零。

## 4. 与论文仍有差距的核心机制

### 4.1 可执行事件图不是论文定义的通用动态事件图

论文定义 `G_t=(V_t,E_t,omega,rho)`，节点应显式包含 owner、timestamp 和 microstep，边应显式包含 data/control/resource-order/completion 类型及 release 规则。当前实现主要是“计算任务 DAG + 临时 network/collective 状态”：

- owner 由 compute/network 事件类型隐式决定，没有通用 owner index；
- transfer 和 collective phase 没有作为一等图节点长期存储；
- 边没有 `kind`、`release` 和资源顺序类型；
- timestamp/microstep 位于消息 batch，而不是每个可执行事件的完整状态；
- sequential/parallel composition 没有独立图操作 API；
- conditional、iteration、运行时插入 recovery graph 尚未实现；
- MPI/GOAL 可转换为任务，但 MPI operation、halo exchange 尚无一等运行时语义。

Collective 确实会在 source 完成后动态产生 flow，但这只是专用状态机，尚不能支持论文所述通用 `Expansion/Contraction/Refinement` 原子图变换。

### 4.2 Active-dependency 缺少论文的 lower-bound/frontier 协议

论文机制的关键不是简单减少参与同步的 simulator，而是每个 producer 对每条活跃跨 DES 边通告 `L_(p->s)`，由 coordinator 计算安全前沿 `F_s`。

当前实现具备：

- orchestrator 动态发布 simulator 级依赖集合；
- broker 根据依赖关系和各 federate 的 `time_requested` 选择 grant；
- 因果越界检查和全局最小值回退。

当前缺少：

- adapter 对活跃 outgoing edge 的 lower-bound 通告接口；
- 每条跨 owner 边的 lower-bound 状态；
- coordinator 对每个 consumer 显式计算 `F_s=min L_(p->s)`；
- lower bound 失效、收回和 graph epoch 的原子一致性协议；
- 证明 backend local next-event 与对外消息 lower bound 一致的契约测试。

现有 `simulator_dependencies()` 只依据是否存在 in-flight compute/network 建立三个 federate 间的粗粒度关系。它能减少部分无关 grant，但不能完全支撑论文第 5 节的公式和安全论证。

### 4.3 Equal-time 只实现了近似的 super-dense ordering

batch 带有 `microstep`，orchestrator 在相同 grant time 时递增它，并按 `(time, microstep, topic, event_id)` 排序。这已经避免依赖 wall-clock 到达顺序，但与论文 `(tau, mu, source, event_id)` 的完整语义仍有差距：

- microstep 是 batch 级，不是 event 级；
- source 没有作为标准信封字段，只能由 topic 间接推断；
- 没有验证跨多个 producer、同 timestamp 多轮零时间反应的全序；
- 部分路径仍依赖 `time_delta=1ns`，等价于引入最小因果时间，而非严格保持同一 `tau`。

### 4.4 通用 exact contraction 依赖声明，不是系统证明

`graph_optimizer.py` 会检查四个 closure 布尔字段均为 true，并检查同 host、线性链、无内部网络边和 SESE 边界。但 state closure、temporal closure 和 resource non-interference 主要由输入作者声明，系统没有从 backend 状态、可观测输出和资源占用中推导它们。

此外，静态 exact contraction 会把多个任务改写成一个 macro task。它没有像 backend-local chain 一样执行全部原始任务并保留内部释放点。因此只有在用户提供的闭包声明和 duration 证书真实有效时，才能认为精确。

### 4.5 论文定义的资源包络宏事件尚未实现

论文宏事件包含边界端口、适用条件、状态变换、资源占用包络、可观测输出、时延区间和细化表示。当前 macro task 只保留：

- region id 和 member 列表；
- duration lower/upper 和 estimate；
- 合并后的 CPU length 或 GPU kernel 列表；
- 最后一项任务的后继边。

当前没有可由 GPUSim/ns-3 执行的跨资源 occupancy envelope，也没有中间 GPU/网络释放点、状态变换和 observable-output contract。论文中 `C1 -> N1 -> C2` 的跨 compute/network 资源包络示例当前不能被收缩为一个仍保持外部并发的宏事件。

### 4.6 Selective refinement 仍是启动前静态选择

当前优化器能够计算最长路上下界、识别可能关键的 region，并按 uncertainty/refine-cost 选择细化对象；小型测试也验证了 critical region 被展开、side region 被保留。

但是它在 `WorkflowController.from_file()` 阶段一次性运行：

- 不消费 backend 运行时状态或 completion 反馈；
- 不在执行过程中修改图；
- 没有多级 `Pi_H` abstraction hierarchy；
- 不支持 phase -> flow -> packet 的逐级运行时 refinement；
- certificate 只覆盖静态 duration DAG，不覆盖资源争用导致的动态 makespan 变化。

所以它符合论文算法的静态原型，不符合论文对 runtime maintenance 的完整表述。

## 5. 实验与论文论断的差距

### 5.1 已有证据

- 18 个 orchestrator/optimizer 单元测试；
- compute -> network -> compute 小型三联邦测试；
- 2-rank Ring collective packet 测试；
- active dependency 小型 grant trace 和同时间消息测试；
- flow macro 单流理论式校验；
- exact contraction、selective refinement 小型功能验证；
- backend-local chain 两组边界轨迹严格 A/B；
- GPU、TP/PP、拓扑和 50--6400 Gbps 带宽 case study；
- 带宽结果符合 `A/B+C`，无限带宽极限由计算和固定传播时延限定。

### 5.2 仍缺少的关键实验

论文源码中的 TODO 是真实缺口，目前还不能删除：

1. 缺少直接 co-simulation 的 host wall-clock 开销分解：broker/FNCS 同步、GPUSim、ns-3 backend event、序列化和进程通信分别占多少。
2. 缺少统一输入和相同 seed 下的五组消融：global/fine、dependency-only、exact contraction、selective refinement、full ComposeDES。
3. 缺少机制级 wall-clock speedup、processed events、grants、cross-DES messages、peak memory 和 event reduction ratio。
4. active dependency 只有小图测试，没有在不同 cross-DES dependency density、simulator 数量和 collective 规模下验证 boundary trace/makespan 等价。
5. approximate contraction 没有统计真实误差、certificate coverage 和 error-budget sweep。
6. AI 20 组 NeuSight preservation 数据存在，但属于源模型复现，不是硬件准确度；当前没有同配置真实 GPU 集群 ground truth。
7. HPC CSV 有重复追加记录且缺统一表头和 ATLAHS baseline join，不能仅凭当前文件自动复算论文所写的 15 组 MARE 2.08% 和最大误差 6.45%。
8. 论文引用的 `figure_new/*.pdf` 不在当前仓库，图表与原始数据之间没有自动生成链路。
9. 论文写的是 x86_64 Docker/RTX 5090 环境，本轮 alpha.4.2 结果来自本机 arm64 环境；需要分别记录，不能混成同一实验平台。

### 5.3 当前论文中需要立即修正的表述

在补齐实现和实验前，以下表述过强：

- `All three mechanisms are implemented.` 应改为“三项机制均有原型，其中 active lower-bound 和通用 runtime macro/refinement 尚为受限实现”。
- “Each adapter exposes ... lower bounds for active outgoing cross-DES edges” 与当前协议不符。
- “Macro-events implement ... resource envelopes ... abstraction hierarchy” 与当前 macro task 字段不符。
- “frontend normalizes ... MPI operations and halo exchanges” 超出当前一等语义支持范围。
- “A tree algorithm produces a different subgraph” 当前只支持 Ring，应标为设计能力或 future work。
- Current Evaluation 中“尚未 isolate active-dependency 或 contraction/refinement”已经部分过时：现有小型消融应写入，但不能替代大规模性能实验。
- source-simulator preservation、thread scaling 和 network sensitivity 的图若继续保留，必须恢复生成脚本、原始输入、运行版本和 `figure_new` 输出。

## 6. 达到论文完整机制所需工作

### P0：投稿前必须完成

1. **实现 lower-bound/frontier 协议。** 为 adapter 增加 per-edge lower-bound advertisement；coordinator 按 graph epoch 原子发布 active edges 与 bounds；broker 或 coordinator 计算每个 consumer 的 safe frontier，并增加 stale-bound/withdraw 测试。
2. **把 executable graph 变成统一运行时对象。** 将 compute、transfer、collective phase/barrier、macro 都建模为 owner-tagged event；边显式保存 kind、release 和可观测性；图操作在 virtual timestamp 上原子提交。
3. **实现可执行资源包络。** backend API 必须能按区间保留 GPU/网络资源占用和释放点；无法证明包络时拒绝 contraction，不能依赖用户勾选 closure=true。
4. **把 refinement 接入运行时。** completion/state feedback 可触发 region 展开；至少支持 macro -> flow，最好支持 flow -> packet；证书需把争用不确定性纳入 bounds。
5. **完成五组统一消融。** 每组输出 simulated makespan、boundary-trace hash、wall-clock、events、grants、messages、memory、误差和 certificate coverage。
6. **修正论文 claim。** 在上述工作完成前降低 Implementation 和 Contributions 的完成度措辞，消除设计描述与现状不一致。

### P1：扩大论文覆盖面

1. 增加 Tree AllReduce 和可插拔 collective algorithm。
2. 增加 MPI operation、halo、conditional、iteration 和 recovery graph 的一等事件语义。
3. 用真实 GPU/网络集群数据做硬件准确度验证，并把“源模型复现”与“硬件准确度”分表报告。
4. 建立从实验命令、JSON/CSV 到论文 PDF 图的自动生成流水线。
5. 在 Linux x86_64 容器环境重跑最终实验，记录镜像 digest、seed、commit manifest 和机器配置。

## 8. 最终判断

alpha.4.2 已经解决最初的架构性问题：DAG 控制面不再由 GPUSim 持有，计算与网络事件均由中间件按 completion 反馈驱动，并且受限 backend-local chain 在不改变精度的前提下减少了跨 DES 交互。

当前最大的缺口不在 NeuSight，而在论文两项核心创新的“完整语义”：active dependency 还需要真实 lower-bound/frontier；event acceleration 还需要可执行资源包络和运行时 refinement。只有补齐这两项并完成统一消融，论文中“完整实现”和“安全加速”的主张才具有足够证据。
