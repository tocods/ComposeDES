# 原生 HiCache 按负载选择读回 CTA

## 原生曲线

A100 PCIe，完整 Qwen3-14B BF16，原生 SGLang v0.5.23。
只修改 page-first 加载路径的 CTA 上限，保持单请求、原有逐层读回
和整层 attention。使用隔离安装。每个请求只生成一个 token，
测量生成 API 延迟。原版 CUDA 上限为 2 CTA。

31,232 个历史 token 都在 CPU cache。每个新增长度 16 对请求，
分两个独立引擎，各 8 对。AB/BA 交替，两臂使用相同 token ID 和
精确匹配的 CPU 缓存命中量。原始日志会逐请求检查加载 CTA、
历史命中 token 数和新增 token 数。输入使用有固定种子的合成 token ID。

| 新增 token | 原版 2 CTA 中位 API 延迟 | 8 CTA 中位 API 延迟 | 中位配对收益 | 95% 配对区间 |
| ---: | ---: | ---: | ---: | --- |
| 512 | 463.21 ms | 454.83 ms | 8.37 ms | [7.63, 9.07] ms |
| 1,024 | 476.19 ms | 464.39 ms | 12.31 ms | [11.99, 13.45] ms |
| 1,536 | 511.40 ms | 568.91 ms | −57.67 ms | [−59.02, −55.98] ms |

同样搬运 4.77 GiB，8 CTA 在两个较短的后缀上有收益，在 1,536
token 上明显退化。实验没有唯一确定切换点。区间为会话内连续
四个配对为块的 bootstrap，只描述所测负载和两次启动。

## CUDA Graph 计时事件对照

固定 31,232/512 的负载，原生 kernel 和 attention 的依赖相同。
每个对照有 32 对，来自两个独立模型进程和四轮 graph 捕获。
捕获时正序、逆序各占一半，执行时 AB/BA 交替。

| 计时方式 | 额外 CUDA Event 数 | 2 CTA 中位 | 8 CTA 中位 | 8 CTA 中位配对收益 |
| --- | ---: | ---: | ---: | ---: |
| 仅首尾端到端 | 0 | 448.07 ms | 441.15 ms | 7.63 ms |
| 每 10 层记录加载结束和 attention 完成 | 8 | 593.14 ms | 579.73 ms | 8.72 ms |
| 逐层分阶段 | 320 | 421.78 ms | 421.15 ms | 0.67 ms |

稀疏计时在正序和逆序捕获时的配对收益分别是 1.74 和 9.26 ms。
完整计时把差值压到了约 0.67 ms，复现了旧阶段模型看到的差值。
即使稀疏计时只增加 8 个事件，绝对延迟也会变化。
端到端模式下，2 CTA 使用同一 graph 重放的 A/A 中位差为
0.03 ms。两份独立捕获的 8 CTA graph 中位差为 −4.77 ms，
反转捕获顺序后偏差仍在。稀疏计时下部分 A/A 会随捕获顺序换符号。
这些对照确定了测量依赖，但仍未分离底层 graph 调度与资源驻留机制。

## 冻结策略的比较方式

训练形状在 15,872 和 31,232 个 CPU 历史 token 下分别使用 512、
1,024、1,536 个新增 token。简单策略共用 84 个原生配对训练样本。
最大化训练集按形状等权的相对配对收益。单阈值仅用新增 token；
浅层树同时允许使用缺失 KV 字节数，每个叶子至少两个训练形状；
小表先按字节数分两档，再在每档独立拟合 token 阈值。经验规则在
留出前冻结。ComposeDES 沿用原争用参数和原 4.57 ms 安全门槛，
不根据留出结果重新校准。

留出使用 15,872 历史 token 配 640、1,216 新增 token，以及
31,232 历史 token 配 768、1,280 新增 token。所有策略都在同一批
物理执行的 2/8 CTA 请求对上评估。启动前验证冻结文件哈希，并在
每条物理请求记录上记录采取该 CTA 的冻结策略。两个缺失字节数
在训练中均出现，独立性在新的计算负载。实验覆盖 CPU 全命中。

简单规则训练的实测生成 API 时间总和约 69.0 s，另有缓存预热和
填充成本。ComposeDES 在四个新形状上需要 24 次独立前向阶段测量，
现场准备约 61.8 s，计时和回读约 6.9 s。它复用了历史标定项目，
原始校准数据共 576 条，相关配置来自其中的子集。两项统计的系统
边界不同，不能用它们声称已降低完整标定成本。

代码位于本目录。运行记录、冻结参数、原始数据、统计和曲线位于
`experiments/megakernel_predictor/runs/mpk-a100/hicache/readback/cta-study/`。

每个留出形状 16 对。正数表示 8 CTA 快于默认 2 CTA。

| CPU 历史 token | 新增 token | 8 CTA 中位配对收益 | 冻结小表 |
| ---: | ---: | ---: | ---: |
| 15,872 | 640 | 5.89 ms | 8 CTA |
| 15,872 | 1,216 | −32.80 ms | 2 CTA |
| 31,232 | 768 | 12.12 ms | 8 CTA |
| 31,232 | 1,280 | 7.43 ms | 8 CTA |

全局阈值和浅层树最终均使用新增 token ≤768 时选 8 CTA。
按缺失字节分档的小表在短前缀档使用 768 阈值，在长前缀档使用
1,280 阈值。对于所测两个档位，小表在留出四个形状上都选中了
两个候选中较快的配置。原生默认和测试安装均维持不变。

小表的平均收益固定形状 bootstrap 95% 区间是 [5.65, 6.91] ms，
平均相对收益约 1.62%。仅有四个留出形状，两个字节档都曾参与训练。
ComposeDES 选对了 31,232/768 和 15,872/1,216 的 CTA，
预测 15,872/640 和 31,232/1,280 会退化 34.08 与 53.05 ms，

仍适合用于诊断，当前原生留出结果没有显示它优于简单表。
