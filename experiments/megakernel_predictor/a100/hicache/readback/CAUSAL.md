# Qwen3-14B HiCache 读回的配对与关键路径实验

## 正确性与测量

A100 PCIe 40 GiB，完整 Qwen3-14B BF16，SGLang v0.5.23
原生 page-first 加载 kernel。受控运行期间只有 KV 读回，KV 写回
字节数为零。每个条件固定读回字节数。CTA 为 kernel 的线程块上限。

正确性实验先用全部驻留的普通 attention 得到参考 logits。负对照
污染所有缺失区域并跳过加载，检查能够识别输出错误。对于每个实际
候选，独立污染缺失 KV，再运行候选和比较词表上全部 logits。共有
86 项检查，所有 logits 有限，86 个首 token 一致。最大绝对差
0.375，最大 RMSE 0.0813。

性能实验每个比较 40 对，分在两个独立启动的 Python/GPU 会话，
每个会话使用新提示。每对相邻运行，AB 和 BA 交替，每轮再随机打乱
各比较的顺序。原始数据保留先后顺序、前一方案、GPU 时钟、温度、
功率和利用率。95% 区间用会话内四次重复为一块的 bootstrap。
两个会话不足以估计跨机器的方差。请求尾延迟的改善不作为本轮结论。

## 配对结果

表中正值表示后一方案缩短 TTFT。单位为 ms。

| 场景 | 对照 → 候选 | 中位配对收益 | 95% 区间 | 会话 A / B |
| --- | --- | ---: | --- | --- |
| 16K 半驻留 | 2 CTA → 1 CTA，整层 | 4.88 | [3.97, 6.02] | 4.64 / 5.81 |
| 16K 半驻留 | 1 CTA 整层 → 只切首层 | 0.86 | [0.24, 1.70] | 1.84 / −0.09 |
| 32K 全读回 | 2 CTA → 独立捕获的相同图，A/A | 1.67 | [0.98, 2.17] | 2.10 / 0.50 |
| 32K 全读回 | 2 CTA → 8 CTA，整层 | 10.70 | [10.23, 12.07] | 8.91 / 13.90 |
| 32K 全读回 | 8 CTA 整层 → 只切末层 | 3.79 | [3.02, 3.92] | 5.28 / 2.57 |
| 32K 全读回 | 2 CTA → 64 CTA，整层 | −126.94 | [−129.66, −125.71] | −124.05 / −132.07 |

16K 半驻留的 A/A 绝对差 P95 为 6.03 ms，32K 全读回为 4.35 ms。
A/A 异常和标注时间插桩的影响应在报告小收益时保留。首层切分的
符号跨会话变化。末层切分的方向一致，绝对收益接近量测波动。

## 关键路径

场景为 31,232 个历史 token 全部从 CPU 读回，再计算 512 个新增 token。
Trace 每方案八次，共记录 32 段实际重叠的执行。逐层记录 H2D 开始
和结束、attention 等 KV 的时间、QKV、部分 attention、合并与后处理。
有向图保留同流顺序和数据就绪依赖，逐个样本回放。

| 配置 | 最后一组 KV 到达 | 实测 TTFT | 乐观反事实去掉并发争用后的 TTFT |
| --- | ---: | ---: | ---: |
| 2 CTA 整层 | 417.21 | 421.79 | 421.55 |
| 8 CTA 整层 | 416.54 | 421.13 | 421.27 |
| 8 CTA 只切末层 | 416.73 | 420.26 | 419.34 |
| 64 CTA 整层 | 418.08 | 570.51 | 421.24 |

去争用反事实用独立测得的各阶段时长保留同样的依赖。2 和 8 CTA
基本没有剩余的去争用收益。64 CTA 的加载末尾只晚约 1 ms，
最后一组 KV 到达后仍有约 153 ms 前向计算。这个对比表明该配置
的主要损失出在共跑期间的前向计算，未分离 SM、L2 或 HBM 成因。

末层切分的栈组装和归约约 0.12 ms。把归约时长设为零，按原图回放
只省约 0.12 ms。进一步用独立全 attention 的时长预算替换所有
分段 FA2 的总时长，并按原份额分配到各组，连同零合并时长的
乐观估计也只再省约 0.28 ms。这组估计适用于所测末层方案。
没有对任意分层策略宣称全局上限。

## 预取距离与留出形状

整层 attention 保持不变。将读回层数限制为最多 1、2 或 4 个待消费
层，与原来一次提交全部 40 层比较。需要补读的下一层在相隔指定
距离的早先层完成 attention 时放行。配额均扫 2 和 8 CTA。

普通 CUDA Graph 回放中，六个有限窗口的中位配对 TTFT 代价为
约 34–57 ms（各自对比 2 CTA 不限窗口，28 对）。详细 trace
的结果需要分开理解。8 CTA、领先一层时，读回服务时长仍为
416.4 ms，复制流的间隙增加约 79 ms，逐层 release 依赖能解释
约 79 ms 的空闲。领先两层和四层的详细 trace 分别为 421.17 和
421.11 ms，不限窗口为 421.13 ms。相邻 A/B 再次验证了这种差别，
仅打开 CUDA Graph 内的逐阶段计时事件，就使两层和四层的执行
分别快约 55 和 64 ms。不加计时的运行中，两层和四层仍比不限
窗口慢 33.8/42.6 ms。两层和四层的下降不能由详细 trace 里的
读回等待解释；测量本身改变了被测执行。因此这三档窗口目前均
没有可推广的性能收益。

会话 A 校准查表与 CTA-only，同时以 A/A 绝对差 P95 加 0.5 ms
得到 4.57 ms 的配置切换门槛。两个简单基线均选择整层 8 CTA，
不限制预取距离。ComposeDES 的重叠速率来自旧的共跑标定，
每个新形状仅另外测独立前向阶段。64 和 1,536 新增 token
的预测在联合测量前按哈希冻结。为使测试都在 32,768 token
内，历史前缀保持 31,232。64 和 1,536 均是实测留出形状。

| 新增 token | 8 CTA 相对 2 CTA 的预测收益 | 实测中位配对收益 | 95% 区间 |
| ---: | ---: | ---: | --- |
| 64 | 0.40 | 0.32 | [0.30, 0.33] |
| 1,536 | −56.19 | −75.07 | [−78.87, −72.32] |

有门槛的策略两个形状都保持 2 CTA。64-token 形状放弃 0.32 ms，
1,536-token 形状避开了简单查表和 CTA-only 的明显退化。原 512-token
形状上，门槛也挡住了模型仅预测为 0.66 ms 的改进，会话 B 的同一对照
实测为 11.7 ms。这体现当前保护规则的保守性。留出形状只重测了
选择器与简单基线实际给出的配置。

原始数据保存于
`experiments/megakernel_predictor/runs/mpk-a100/hicache/readback/causal/`。
`run_causal.py` 分别运行正确性、配对、trace、窗口和新形状。
`causal_analysis.py` 计算区间与反事实，`select_window.py` 生成冻结策略。


## 原生 SGLang 复验

在 SGLang v0.5.23 的隔离副本中，仅让 page-first H2D 加载 kernel
读取实验 CTA 上限。沿用原来的逐层读回、整层 attention 与原版
请求调度。两个独立引擎分别测十对，AB/BA 交替。每对输入一致，
两臂均由原生 cache report 确认 31,232 个 token 全部命中 CPU，
GPU 命中为零。首 token 逐对匹配。

2 CTA 的单 token API 中位延迟为 455.57 ms，8 CTA 为 448.84 ms。
中位配对收益 6.72 ms，95% 区间 [6.48, 7.37] ms，两会话
分别为 7.43 和 5.49 ms。按对中位收益和原版中位延迟计算，约
1.47%。原生复验覆盖 512 新增 token，仍按 SGLang 原有策略维护
缓存。实验补丁未应用到服务器的原 SGLang 安装。
