# 实验结论与研究判断

本轮完成了完整 Qwen3-8B 的真实 CUDA kernel 图提取、随机加边、GCN+DQN 训练及与 ComposeDES 的等预算比较。结果不支持在当前单请求、权重与前缀 KV 全驻留的执行图上宣称辅助边优化获得稳定收益，也未证明 ComposeDES 优于 GCN+DQN。结果表和原始数据分别见 [RESULTS.md](RESULTS.md) 与 [数据归档](reference/artifacts.json)。

## 1. 收益空间先于学习算法

512/1 输入的实际图含 2,138 个节点、1,991 个 kernel 和 2,494 条原始依赖。随机探索测量了 10,000 个不同图。搜索第一名在冻结后的独立确认中，相对原图的配对收益为 +0.0033%，95% bootstrap 区间为 [−0.0355%, +0.0388%]。这一结果没有支持明显的可重复收益。

这不是辅助边优化的理论上限。随机探索没有穷尽合法图，也没有覆盖更多并发请求或更多模型；它只说明在已声明的动作空间和采样分布下，没有找到可复现的主要收益。

## 2. 学习与搜索结果

各方法使用 3,200 次训练图测量，并在每个留出形状上使用 512 次目标图测量。训练权重在留出前冻结，最终选中的图在新进程中统一交错确认。

| 留出前缀/新增 token | 随机搜索配对收益 | GCN+DQN 配对收益 | ComposeDES 配对收益 |
|---|---:|---:|---:|
| 2048/1 | −0.0230% | −0.0220% | −0.0351% |
| 1024/64 | +0.0193% | +0.0351% | +0.0138% |

以上全部区间包含零。2048/1 中 GCN+DQN 和 ComposeDES 最终均选中 0 条辅助边；1024/64 中 GCN+DQN 选中 2 条，ComposeDES 仍选中 0 条。0 条辅助边与原图依赖相同，测量差异不能归因于调度改进。

无目标完整图反馈的直接迁移也未建立优势：在 2048/1 中，GCN+DQN 与 ComposeDES 分别慢约 0.31% 和 0.13%；1024/64 中二者与原图的差异不显著。因此，当前结果不能解释成“学习找到了更好的调度，只是搜索预算不够”。

所有方法均完成 32-token 生成。2048/1 的输出吞吐约 59.4 token/s，1024/64 也约 59.4 token/s。首个 forward 之后采用共同的 decode 路径，这些整体吞吐的微小差别不支持额外的生成加速结论。

## 3. 可以解释什么，尚不能解释什么

显式保留 Q/K/V 和 gate/up 的并行分支比相同运算的串行图更快；这属于源图的并行表达收益，不属于辅助边、GCN+DQN 或 ComposeDES 的收益。先降低源图质量再通过优化恢复，不能作为本方法的主要贡献。

探索图有 1,490 个最长路径拓扑层级，同一层级最多 3 个节点。层与层之间的串行数据依赖明显限制了图级并行调度空间。这提供了一个合理解释，但尚不是对 GPU 准入、内存争用或 kernel 启动机制的因果证明，也不能据此断言所有 Transformer 图都无优化空间。

原论文以 SSTA 为对象，讨论了通过增加少量依赖缓解过度并行的收益。本轮更换应用和 GPU 后，没有重现其明显加速，不能据此否定原论文。后续若继续这条路线，需要先在真实工作负载中找到具有显著、可重复调度收益的源图，再比较学习方法；单纯增加 DQN 训练轮数或调节 ComposeDES 参数，目前缺乏收益空间证据。

## 4. 复现边界

本实现遵循论文公开的六项特征、两跳 GCN、0/1/2 节点层级动作、DQN 网络和训练超参数。原文未完整指定的 GCN 维度与归一化细节、目标节点选择和每轮动作数已明确记录。等实测预算比较属于本实验扩展，不等同于作者原有评价协议。

本轮采用一个训练种子、两个留出形状和一台有已知显存异常的 A100。按要求只评价性能，未执行模型输出正确性筛选。输入形状留出不等于跨应用依赖拓扑留出，当前置信区间也不包含多次独立训练或多台 GPU 的不确定性。

参考：[Optimizing CUDA Graph Scheduling with Reinforcement Learning: A Case Study in SSTA Propagation](https://tsung-wei-huang.github.io/papers/2025-MLCAD.pdf)。
